# Project 6. Manufacturing IT / OT Cyber-Physical Network: Secure, Segmented, & Resilient

## 6.6 Simplified Troubleshooting Workflow

Project 6 applies a structured troubleshooting methodology to identify, investigate, isolate, resolve, validate, and document manufacturing network connectivity, security, redundancy, and infrastructure service problems. The solution uses Cisco IOS CLI diagnostics, interface verification, VLAN and IEEE 802.1Q trunk inspection, ACL testing, Rapid PVST+ failover validation, and network service verification to support reliable manufacturing operations.

![Project 6 — Simplified Troubleshooting Workflow](infographics/6.6%20Simplified-Troubleshooting-Workflow.png)

Troubleshooting Workflow: Verify Connectivity → Check VLANs & Trunks → Validate Security → Test Redundancy → Confirm Services.

## 1. Verify Connectivity

Confirm Basic Network Reachability, Interface Status, and Layer 3 Connectivity

| #  | Engineering Activity                 | Diagnostic / Verification Method                                                       | Expected Result                                                             |
| -- | ------------------------------------ | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 1  | Check Physical Interface Status      | Inspect interface operational states on R1, SW1, and SW2.                              | Required interfaces are operational.                                        |
| 2  | Check Logical Interface Status       | Verify configured router subinterfaces, switch interfaces, and associated IP settings. | Interfaces are configured and operational as intended.                      |
| 3  | Verify Device Reachability           | Use ICMP ping tests between authorized network devices.                                | Expected network paths are reachable.                                       |
| 4  | Verify Corporate Connectivity        | Test PC1 connectivity within Corporate VLAN 10.                                        | Corporate endpoint communicates with its gateway and authorized resources.  |
| 5  | Verify Guest Connectivity            | Test PC2 connectivity within Guest VLAN 40.                                            | Guest endpoint reaches its gateway and approved destinations.               |
| 6  | Verify Services Connectivity         | Test SRV1 reachability at `10.10.50.10` on Services VLAN 50.                           | Centralized infrastructure services are reachable from authorized networks. |
| 7  | Confirm Default Gateway Reachability | Ping the appropriate R1 router subinterface from supported endpoints.                  | Endpoints reach their configured VLAN gateways.                             |
| 8  | Validate IPv4 Addressing             | Inspect client IP addresses, subnet masks, and default gateways.                       | Endpoints use the correct network configuration.                            |
| 9  | Check Inter-VLAN Connectivity        | Test communication between VLANs where permitted by security policies.                 | Authorized Layer 3 connectivity succeeds.                                   |
| 10 | Investigate Connectivity Failures    | Inspect interface status, addressing, routing, and ICMP test results.                  | Connectivity problems are isolated to affected devices or network paths.    |
| 11 | Primary Outcome                      | Physical, logical, endpoint, and gateway connectivity verified.                        | Basic network reachability and device status confirmed.                     |

### Common Cisco IOS Commands

| Command                   | Engineering Purpose                                            |
| ------------------------- | -------------------------------------------------------------- |
| `show ip interface brief` | Inspect router interface IP addresses and operational states.  |
| `show interfaces status`  | Review switch interface connectivity and operational status.   |
| `ping <ip-address>`       | Test ICMP reachability to a specified destination.             |
| `traceroute <ip-address>` | Inspect the Layer 3 path toward a destination.                 |
| `show cdp neighbors`      | Discover directly connected Cisco devices when CDP is enabled. |

## 2. Check VLANs & Trunks

Validate VLAN Configuration, Access Port Assignments, and IEEE 802.1Q Trunk Connectivity

| #  | Engineering Activity                  | Diagnostic / Verification Method                                                           | Expected Result                                                                 |
| -- | ------------------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| 1  | Verify VLAN Configuration             | Inspect configured VLANs on SW1 and SW2.                                                   | Required VLANs exist on the appropriate switches.                               |
| 2  | Validate Corporate VLAN               | Confirm VLAN 10 is configured and PC1 is assigned to the appropriate access port.          | Corporate endpoint is correctly segmented.                                      |
| 3  | Validate Engineering VLAN             | Verify VLAN 20 exists where required.                                                      | Engineering network segmentation is configured.                                 |
| 4  | Validate OT VLAN                      | Verify VLAN 30 exists where required.                                                      | Operational technology network segmentation is configured.                      |
| 5  | Validate Guest VLAN                   | Confirm VLAN 40 is configured and PC2 is assigned to the appropriate access port.          | Guest endpoint is correctly segmented.                                          |
| 6  | Validate Services VLAN                | Confirm VLAN 50 is configured and SRV1 is assigned to the appropriate access port.         | Centralized services are connected to the correct VLAN.                         |
| 7  | Validate Management VLAN              | Verify VLAN 99 is configured where required.                                               | Management network segmentation is defined.                                     |
| 8  | Verify Access Port Membership         | Inspect access port VLAN assignments.                                                      | Endpoints belong to their designated VLANs.                                     |
| 9  | Check IEEE 802.1Q Trunk Status        | Inspect trunk interfaces between R1–SW1 and SW1–SW2.                                       | Required trunk connections are operational.                                     |
| 10 | Verify Allowed VLANs                  | Confirm VLANs 10, 20, 30, 40, 50, and 99 are permitted across the appropriate trunk links. | Required VLAN traffic can traverse the intended network paths.                  |
| 11 | Validate Switchport Configuration     | Inspect switchport mode, access VLAN, and trunk settings.                                  | Interfaces use the intended switching configuration.                            |
| 12 | Verify MAC Address Learning           | Inspect learned MAC addresses on switch interfaces.                                        | Expected endpoints are visible within their VLANs.                              |
| 13 | Identify Trunk Configuration Problems | Investigate incorrect tagging, missing VLANs, or interface configuration mismatches.       | VLAN transport problems are isolated and corrected.                             |
| 14 | Primary Outcome                       | VLAN configuration, access port assignments, and IEEE 802.1Q trunk connectivity verified.  | Consistent Segmentation. Correct VLAN Transport. Reliable Layer 2 Connectivity. |

### Common Cisco IOS Commands

| Command                      | Engineering Purpose                                           |
| ---------------------------- | ------------------------------------------------------------- |
| `show vlan brief`            | Display configured VLANs and access port assignments.         |
| `show interfaces trunk`      | Inspect active trunk ports and permitted VLANs.               |
| `show interfaces switchport` | Review switchport modes, VLAN membership, and trunk settings. |
| `show spanning-tree`         | Inspect spanning-tree operation and interface roles.          |

## 3. Validate Security

Verify ACL Enforcement, Guest Network Isolation, and Authorized Inter-VLAN Communication

| #  | Engineering Activity                 | Diagnostic / Verification Method                                                                           | Expected Result                                                                   |
| -- | ------------------------------------ | ---------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 1  | Inspect ACL Configuration            | Review configured ACL rules on R1.                                                                         | Access policies match the intended security requirements.                         |
| 2  | Test ACL Permit Rules                | Generate authorized traffic between permitted network segments.                                            | Approved communication succeeds.                                                  |
| 3  | Test ACL Deny Rules                  | Generate traffic that should be blocked by security policies.                                              | Unauthorized communication is denied.                                             |
| 4  | Verify Guest Isolation               | Test PC2 access to protected internal networks.                                                            | Guest traffic cannot reach prohibited destinations.                               |
| 5  | Protect Corporate Resources          | Test Guest VLAN 40 access to Corporate VLAN 10.                                                            | Unauthorized guest-to-corporate traffic is denied.                                |
| 6  | Protect Engineering Resources        | Test Guest VLAN 40 access to Engineering VLAN 20.                                                          | Unauthorized guest-to-engineering traffic is denied.                              |
| 7  | Protect OT Resources                 | Test Guest VLAN 40 access to OT VLAN 30.                                                                   | Unauthorized guest-to-OT traffic is denied.                                       |
| 8  | Protect Services Resources           | Test Guest VLAN 40 access to Services VLAN 50.                                                             | Unauthorized guest-to-services traffic is denied.                                 |
| 9  | Protect Management Resources         | Test Guest VLAN 40 access to Management VLAN 99.                                                           | Unauthorized guest-to-management traffic is denied.                               |
| 10 | Verify Authorized Inter-VLAN Routing | Test permitted communication through R1 subinterfaces.                                                     | Approved network communication succeeds.                                          |
| 11 | Inspect ACL Match Counters           | Review ACL counters after generating test traffic.                                                         | Expected permit and deny rules register matching traffic.                         |
| 12 | Review Security Logs                 | Inspect relevant Syslog events and ACL logging evidence.                                                   | Security-related network activity is recorded where logging is configured.        |
| 13 | Validate ACL Placement               | Inspect ACL application on the intended router interfaces and directions.                                  | Traffic filtering is applied at the correct network boundaries.                   |
| 14 | Investigate Security Policy Failures | Review ACL rule order, source/destination addresses, interface assignments, and observed traffic behavior. | Incorrect access restrictions are identified and corrected.                       |
| 15 | Primary Outcome                      | ACL permit and deny rules validated, guest isolation confirmed, and authorized communication preserved.    | Enforced Security Policies. Protected Internal Networks. Controlled Connectivity. |

### Common Cisco IOS Commands

| Command                         | Engineering Purpose                                           |
| ------------------------------- | ------------------------------------------------------------- |
| `show access-lists`             | Display ACL rules and associated match counters.              |
| `show ip access-lists`          | Inspect IPv4 ACLs and traffic matches.                        |
| `show logging`                  | Review locally recorded network and security events.          |
| `show ip interface <interface>` | Inspect IP interface configuration and applied ACL direction. |
| `ping <ip-address>`             | Test whether specific traffic is permitted or denied.         |

## 4. Test Redundancy

Validate Rapid PVST+ Operation, Redundant Trunk Links, and Layer 2 Failover

| #  | Engineering Activity               | Diagnostic / Verification Method                                                                                   | Expected Result                                                      |
| -- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------- |
| 1  | Verify Rapid PVST+ Configuration   | Inspect spanning-tree mode and VLAN-specific spanning-tree operation.                                              | Rapid PVST+ is configured and operational.                           |
| 2  | Confirm Root Bridge Selection      | Inspect spanning-tree root information on SW1 and SW2.                                                             | SW1 is recognized as the intended root bridge.                       |
| 3  | Verify Redundant Trunk Links       | Inspect the two IEEE 802.1Q connections between SW1 and SW2.                                                       | Redundant inter-switch links are configured.                         |
| 4  | Inspect Spanning-Tree Port Roles   | Review root, designated, and alternate port roles.                                                                 | Redundant paths have appropriate spanning-tree roles.                |
| 5  | Validate Loop Prevention           | Confirm redundant links are placed into appropriate forwarding or discarding states.                               | Layer 2 forwarding loops are prevented.                              |
| 6  | Simulate a Switching Link Failure  | Disable or disconnect a selected active inter-switch link in the controlled laboratory.                            | Network failover behavior is initiated.                              |
| 7  | Verify Rapid PVST+ Reconvergence   | Observe spanning-tree state changes after link failure.                                                            | The network converges to a valid forwarding topology.                |
| 8  | Confirm Alternate Forwarding Path  | Inspect the remaining inter-switch link and its forwarding state.                                                  | An alternate path becomes operational.                               |
| 9  | Validate Connectivity Preservation | Repeat authorized endpoint and gateway connectivity tests after reconvergence.                                     | Permitted network connectivity is restored or maintained.            |
| 10 | Inspect Interface Status           | Review interface operational states during and after failover.                                                     | Expected interfaces and remaining links operate correctly.           |
| 11 | Review Relevant Logs               | Inspect device events associated with link changes and spanning-tree operation.                                    | Link and topology changes are documented where logging is available. |
| 12 | Restore Normal Topology            | Re-enable the affected link and verify spanning-tree reconvergence.                                                | The network returns to the intended redundant configuration.         |
| 13 | Document Failover Evidence         | Capture spanning-tree outputs, interface states, connectivity tests, and observed recovery behavior.               | Reusable network resilience evidence is preserved.                   |
| 14 | Primary Outcome                    | Redundant Layer 2 connectivity and Rapid PVST+ failover behavior verified through controlled link failure testing. | Validated Redundancy. Loop Prevention. Improved Network Resilience.  |

### Common Cisco IOS Commands

| Command                        | Engineering Purpose                                                      |
| ------------------------------ | ------------------------------------------------------------------------ |
| `show spanning-tree`           | Inspect spanning-tree topology, root bridge information, and port roles. |
| `show spanning-tree vlan <id>` | Inspect spanning-tree operation for a specific VLAN.                     |
| `show interfaces status`       | Verify interface connectivity and operational state.                     |
| `show logging`                 | Review relevant link and spanning-tree events.                           |
| `ping <ip-address>`            | Validate authorized connectivity before and after failover.              |
