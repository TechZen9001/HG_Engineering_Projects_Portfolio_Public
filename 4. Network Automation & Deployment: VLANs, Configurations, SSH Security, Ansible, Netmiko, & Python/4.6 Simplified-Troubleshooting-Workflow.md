# Project 4. Network Automation & Deployment: VLANs, Configurations, SSH Security, Ansible, Netmiko, & Python

## 4.6 Simplified Troubleshooting Workflow

Project 4 applies a structured six-stage troubleshooting methodology to identify SSH connectivity failures, VLAN configuration mismatches, Python automation errors, Ansible playbook issues, and unsuccessful network deployments before verifying successful remediation.

![Project 4 — Simplified Troubleshooting Workflow](infographics/4.6%20Simplified-Troubleshooting-Workflow.png)


| Executive Summary           | Description                                                                                                                                                                              |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Project Title               | Network Automation & Deployment: VLANs, Configurations, SSH Security, Ansible, Netmiko, & Python                                                                                         |
| Project Purpose             | Establish a structured troubleshooting framework to identify, investigate, resolve, validate, and document network automation and configuration deployment problems.                     |
| Primary Objective           | Diagnose SSH connectivity failures, VLAN configuration mismatches, Python automation errors, Ansible playbook issues, and unsuccessful network deployments.                              |
| Troubleshooting Methodology | Detect → Analyze → Isolate → Resolve → Validate → Document.                                                                                                                              |
| Simplified Workflow         | Identify → Inspect → Automate → Validate → Document & Back Up.                                                                                                                           |
| Core Technologies           | Python, Netmiko, Ansible, ExtremeXOS, Linux, SSH, RSA Keys, YAML, GitLab, and CLI diagnostics.                                                                                           |
| Target Infrastructure       | Four ExtremeXOS access switches managed through a centralized Linux automation controller and core network infrastructure.                                                               |
| Engineering Principles      | Evidence-based investigation, secure authentication, accurate inventories, YAML validation, controlled configuration changes, backups, error handling, and post-deployment verification. |
| Expected Outcomes           | Faster fault isolation, consistent remediation, successful configuration deployment, validated network functionality, and reusable engineering documentation.                            |
| Business Value              | Reduced downtime, improved network reliability, standardized troubleshooting, stronger security, and continuous operational improvement.                                                 |
| Strategic Principle         | Identify → Inspect → Automate → Validate → Document & Back Up.                                                                                                                           |

## 1. Identify the Issue

Understand the Problem and Gather Diagnostic Information

| #  | Troubleshooting Activity               | Engineering Implementation                                                                                                                         | Expected Outcome                                                           |
| -- | -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 1  | Review Error Messages                  | Examine Python exceptions, Netmiko errors, Ansible task failures, and ExtremeXOS CLI responses.                                                    | Identify initial symptoms and failure indicators.                          |
| 2  | Inspect Automation Logs                | Review script execution logs, playbook output, and relevant system messages.                                                                       | Collect evidence of unsuccessful automation operations.                    |
| 3  | Verify Device Reachability             | Use `ping` and SSH connectivity checks against managed switch IP addresses.                                                                        | Determine whether affected devices are reachable.                          |
| 4  | Identify Affected Infrastructure       | Determine which ExtremeXOS switch, VLAN, interface, configuration, or automation task is affected.                                                 | Establish the incident scope.                                              |
| 5  | Investigate SSH Connectivity           | Check for refused connections, timeouts, or unreachable SSH services.                                                                              | Identify potential management connectivity failures.                       |
| 6  | Investigate SSH Authentication         | Review authentication failures, RSA key configuration, and authorized account settings.                                                            | Determine whether access credentials or key configuration are responsible. |
| 7  | Identify Python Automation Errors      | Examine Python exceptions, incorrect script results, and failed command execution.                                                                 | Determine whether the issue originates in Python automation logic.         |
| 8  | Identify Netmiko Issues                | Review device connection parameters, platform selection, SSH sessions, and CLI command responses.                                                  | Identify connectivity or command execution failures.                       |
| 9  | Identify Ansible Execution Failures    | Examine playbook errors, inventory references, YAML syntax, and failed tasks.                                                                      | Determine whether configuration management is functioning correctly.       |
| 10 | Identify VLAN Configuration Mismatches | Compare expected VLAN configurations with observed switch settings.                                                                                | Identify missing, incorrect, or inconsistent VLAN assignments.             |
| 11 | Investigate Backup Failures            | Review backup script results and determine whether configuration files were created successfully.                                                  | Identify incomplete or unsuccessful configuration backups.                 |
| 12 | Investigate GitLab Issues              | Check Git status, branch information, commit history, and repository synchronization.                                                              | Identify missing or uncommitted automation changes.                        |
| 13 | Classify the Incident                  | Determine whether the issue involves connectivity, authentication, inventory data, YAML formatting, automation execution, or device configuration. | Establish the appropriate troubleshooting path.                            |
| 14 | Preserve Initial Evidence              | Record error messages, execution output, affected devices, and relevant configuration information before corrective actions.                       | Maintain a reliable troubleshooting baseline.                              |

## 2. Check Device State

Verify Device Status and Confirm Current Configuration

| #  | Verification Activity                | Engineering Implementation                                                                                    | Expected Outcome                                                       |
| -- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 1  | Verify Switch Reachability           | Test connectivity to the managed ExtremeXOS switches using `ping` and SSH.                                    | Confirm network management connectivity.                               |
| 2  | Verify SSH Service                   | Inspect SSH2 configuration and confirm SSH access is enabled on authorized devices.                           | Determine whether remote administration is operational.                |
| 3  | Verify SSH Port Availability         | Test TCP port 22 connectivity and investigate connection failures.                                            | Identify unavailable or blocked SSH services.                          |
| 4  | Validate RSA Key Authentication      | Verify the public/private key pair, authorized key association, and SSH login results.                        | Confirm secure key-based authentication.                               |
| 5  | Review Device Status                 | Execute supported ExtremeXOS CLI commands to inspect device health and operational state.                     | Confirm current switch functionality.                                  |
| 6  | Inspect VLAN Configurations          | Retrieve existing VLAN IDs, names, and relevant configuration details.                                        | Identify current network segmentation.                                 |
| 7  | Verify VLAN Membership               | Inspect VLAN membership and associated switch ports.                                                          | Confirm intended VLAN assignments.                                     |
| 8  | Verify Interface Status              | Review relevant interface operational state and configuration.                                                | Identify disabled, disconnected, or incorrectly configured interfaces. |
| 9  | Inspect Configuration Settings       | Compare observed switch settings against approved configuration requirements.                                 | Identify configuration drift or mismatches.                            |
| 10 | Review System Logs                   | Inspect device and automation logs for relevant operational errors.                                           | Correlate device behavior with automation failures.                    |
| 11 | Validate Device Inventory            | Confirm management IP addresses, hostnames, device groups, and connection parameters.                         | Eliminate incorrect inventory data as a failure source.                |
| 12 | Validate Netmiko Platform Settings   | Confirm that connection parameters and the selected device driver match the managed ExtremeXOS platform.      | Support reliable Netmiko SSH connectivity.                             |
| 13 | Verify Ansible Connectivity Settings | Inspect inventory variables, network operating system selection, SSH parameters, and authentication settings. | Confirm correct Ansible device access configuration.                   |
| 14 | Review Configuration Backups         | Inspect available backup files and compare them with relevant device configurations.                          | Establish recovery references and configuration history.               |
| 15 | Confirm Current Network State        | Consolidate reachability, SSH, VLAN, interface, configuration, and log findings.                              | Establish an accurate baseline before remediation.                     |

## 3. Run Automation

Deploy the Solution Using Approved Python Scripts and Ansible Playbooks

| #  | Automation Activity                  | Engineering Implementation                                                                                          | Expected Outcome                                          |
| -- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| 1  | Select the Appropriate Automation    | Identify the Python script or Ansible playbook corresponding to the diagnosed issue.                                | Apply the correct automation workflow.                    |
| 2  | Verify Execution Prerequisites       | Confirm device reachability, authentication, inventories, dependencies, and configuration requirements.             | Reduce avoidable execution failures.                      |
| 3  | Validate Python Scripts              | Inspect script logic, required libraries, input data, and error handling.                                           | Confirm Python automation readiness.                      |
| 4  | Validate Netmiko Connectivity        | Establish authenticated SSH sessions and verify supported command execution.                                        | Confirm programmable device access.                       |
| 5  | Validate Ansible Inventory           | Check device addresses, group definitions, connection settings, and target hosts.                                   | Confirm correct automation targeting.                     |
| 6  | Validate YAML Syntax                 | Inspect indentation, spacing, key names, task structure, and parser output.                                         | Identify and correct YAML formatting errors.              |
| 7  | Validate Ansible Playbooks           | Review task definitions, modules, command syntax, and device compatibility.                                         | Confirm playbook readiness.                               |
| 8  | Verify SSH Authentication            | Confirm approved RSA SSH keys and administrative accounts are configured correctly.                                 | Establish secure automation access.                       |
| 9  | Execute Python Automation            | Run the appropriate Python script for VLAN discovery, configuration backup, deployment, or validation.              | Complete the intended network automation task.            |
| 10 | Execute Ansible Playbooks            | Run approved playbooks for standardized configuration or administrative account management.                         | Apply repeatable multi-device changes.                    |
| 11 | Apply Approved Configuration Changes | Execute authorized switch configuration corrections or administrative operations.                                   | Resolve identified configuration problems.                |
| 12 | Correct Inventory Issues             | Update incorrect management addresses, host groups, connection parameters, or inventory references.                 | Restore accurate automation targeting.                    |
| 13 | Correct SSH Issues                   | Repair approved SSH service, key association, or authentication settings.                                           | Restore secure device connectivity.                       |
| 14 | Correct YAML and Playbook Errors     | Resolve invalid indentation, unsupported tasks, incorrect module parameters, or execution problems.                 | Restore successful Ansible execution.                     |
| 15 | Correct Python and Netmiko Errors    | Address script exceptions, connection failures, invalid command handling, and incorrect outputs.                    | Restore reliable Python automation.                       |
| 16 | Correct VLAN Configuration Issues    | Apply approved VLAN creation, naming, membership, or interface configuration changes.                               | Restore intended departmental VLAN configurations.        |
| 17 | Review Automation Output             | Examine execution logs, CLI responses, Ansible task results, and script output.                                     | Confirm whether corrective actions executed successfully. |
| 18 | Handle Unsuccessful Execution        | Stop or safely contain failed operations, investigate errors, and use approved rollback procedures where necessary. | Prevent uncontrolled or incomplete configuration changes. |
| 19 | Record Corrective Actions            | Preserve executed commands, script results, playbook output, and relevant configuration changes.                    | Maintain traceable remediation evidence.                  |

| Automation Reporting         | Missing or inaccurate logs and reports.              | Execution logs, JSON output, validation records.                 | Correct reporting logic and verify generated evidence.                      |

## Troubleshooting Principles

| -- | -------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |

| 2  | Secure Authentication            | Verify SSH key-based access without exposing private keys or credentials.                                        | Protects administrative access.                                                          |
| 3  | Inventory Accuracy               | Confirm device addresses, platform settings, and connection parameters.                                          | Prevents incorrect automation targeting.                                                 |
| 4  | YAML Validation                  | Check indentation, syntax, task structure, and inventory formatting.                                             | Reduces Ansible execution failures.                                                      |
| 5  | Controlled Configuration Changes | Apply approved commands and validated automation scripts.                                                        | Reduces deployment risk.                                                                 |
| 6  | Configuration Backups            | Preserve switch configurations before potentially disruptive changes.                                            | Supports recovery readiness.                                                             |
| 7  | Error Handling                   | Detect authentication failures, command errors, and unsuccessful automation tasks.                               | Prevents unsafe or incomplete execution.                                                 |
| 8  | Rollback Readiness               | Maintain recovery procedures for failed deployments.                                                             | Improves operational resilience.                                                         |
| 9  | Post-Deployment Validation       | Verify VLANs, administrative accounts, device connectivity, and intended configurations.                         | Confirms successful deployment and expected network functionality.                       |
| 10 | Version Control                  | Track Python scripts, Ansible playbooks, inventories, and automation changes using Git and GitLab.               | Improves change traceability, accountability, and configuration management.              |
| 11 | Technical Documentation          | Record failures, root causes, corrective actions, execution logs, and validation evidence.                       | Supports repeatable troubleshooting, knowledge transfer, and engineering accountability. |
| 12 | Continuous Improvement           | Refine Python scripts, inventories, playbooks, and troubleshooting procedures using documented findings.         | Improves automation reliability, operational efficiency, and future deployments.         |

## Workflow Summary

Identify → Inspect → Automate → Validate → Document & Back Up

| Workflow Stage        | Primary Engineering Activity                                                                                                                                                                          | Expected Outcome                                                                   | Operational Value                                                                     |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 1. Identify the Issue | Review error messages and logs, test device reachability using ping and SSH, identify affected switches or VLANs, and classify connectivity, authentication, or automation failures.                  | Problem identified, incident scope established, and diagnostic evidence collected. | Faster incident identification and improved troubleshooting accuracy.                 |
| 2. Check Device State | Execute ExtremeXOS verification commands, inspect VLAN membership and interface status, review configuration settings and logs, and confirm SSH access.                                               | Current device state and configuration verified; potential root causes isolated.   | More accurate fault isolation and reduced troubleshooting uncertainty.                |
| 3. Run Automation     | Execute appropriate Python scripts or Ansible playbooks, apply approved corrective actions, and troubleshoot inventory, YAML, SSH, Netmiko, or module errors.                                         | Automation or configuration issue corrected, with execution results recorded.      | Repeatable remediation, reduced manual effort, and consistent network administration. |
| 4. Validate Results   | Verify VLAN creation, membership, interface assignments, network connectivity, SSH authentication, and expected configuration changes.                                                                | Intended changes confirmed and network functionality validated.                    | Improved deployment reliability and reduced risk of unresolved configuration errors.  |
| 5. Document & Back Up | Save device configurations, archive backups and execution logs, document root causes and corrective actions, and commit reviewed automation artifacts to GitLab.                                      | Configuration backups preserved and reusable engineering documentation maintained. | Improved recovery readiness, change traceability, and knowledge retention.            |
| Repeat                | Apply documented lessons learned to improve scripts, playbooks, inventories, validation procedures, and troubleshooting runbooks.                                                                     | Continuously refined network automation and troubleshooting framework.             | More reliable, secure, and scalable network operations.                               |
| Executive Takeaway    | A structured troubleshooting process identifies automation failures, verifies device state, applies controlled remediation, validates results, and preserves configurations and engineering evidence. | Repeatable, secure, and validated network troubleshooting.                         | Reduced Downtime. Improved Reliability. Continuous Improvement.                       |
| Long-Term Value       | Identify → Inspect → Automate → Validate → Document & Back Up → Repeat.                                                                                                                               | Standardized troubleshooting and reliable network automation.                      | A More Secure, Reliable, and Automated Network.                                       |
