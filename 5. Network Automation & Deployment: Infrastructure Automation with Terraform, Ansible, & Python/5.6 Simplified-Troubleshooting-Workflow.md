# Project 5 – Network Automation & Deployment: Infrastructure Automation with Terraform, Ansible, & Python

## 5.6 Simplified Troubleshooting Workflow

Project 5 applies a structured six-stage troubleshooting methodology to investigate Terraform deployment failures, AWS resource configuration errors, SSH connectivity problems, Ansible playbook issues, and Python validation failures.

![Project 5 — Simplified Troubleshooting Workflow](infographics/5.6%20Simplified-Troubleshooting-Workflow.png)

Troubleshooting Workflow: Check Deployment → Check Instance State → Test Connectivity → Check Configuration → Validate & Report.

## 1. Check Deployment

Verify Terraform Infrastructure Provisioning and AWS Resource Creation

| #  | Troubleshooting Activity           | Engineering Implementation / Verification                                                                              | Expected Outcome                                                     |
| -- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 1  | Review Terraform Plan              | Inspect `terraform plan` output to confirm intended AWS infrastructure resources and proposed changes.                 | Expected infrastructure changes identified.                          |
| 2  | Review Terraform Apply             | Examine `terraform apply` output for provisioning success, failed resources, and deployment errors.                    | Terraform execution status confirmed.                                |
| 3  | Verify AWS Resource Creation       | Confirm that the expected VPC, subnets, Security Groups, routing components, and EC2 instances exist.                  | Required AWS infrastructure resources identified.                    |
| 4  | Terraform Initialization           | Review `terraform init` output for provider installation, dependency, or initialization failures.                      | Terraform initialization problems identified.                        |
| 5  | Terraform Configuration Validation | Execute `terraform validate` to check configuration syntax and structural validity.                                    | Terraform configuration validation completed.                        |
| 6  | Terraform Provider Configuration   | Verify the AWS provider, region, authentication settings, and required resource definitions.                           | Appropriate provider configuration confirmed.                        |
| 7  | AWS Authentication and IAM         | Verify AWS credentials and permissions required to provision and inspect infrastructure.                               | Authorized AWS access confirmed.                                     |
| 8  | VPC Configuration                  | Inspect VPC addressing, resource definitions, and associated network settings.                                         | Intended VPC configuration verified.                                 |
| 9  | Subnet Configuration               | Confirm expected subnet creation, addressing, and resource placement.                                                  | Subnet configuration verified.                                       |
| 10 | Security Group Deployment          | Verify that required Security Groups were created with approved traffic rules.                                         | Network access controls identified.                                  |
| 11 | EC2 Resource Deployment            | Confirm Terraform successfully requested and provisioned Ubuntu and RHEL EC2 instances.                                | Expected compute resources created.                                  |
| 12 | Terraform State Inspection         | Review managed infrastructure state and relevant resource attributes without exposing sensitive state data.            | Infrastructure tracking information verified.                        |
| 13 | Terraform Error Analysis           | Investigate invalid resource attributes, dependency errors, provider failures, and unsuccessful deployment operations. | Probable provisioning failures isolated.                             |
| 14 | Deployment Log Review              | Preserve relevant Terraform command output and diagnostic messages.                                                    | Reusable deployment troubleshooting evidence.                        |
| 15 | Controlled Remediation             | Correct approved Terraform definitions and review proposed changes before reapplying.                                  | Infrastructure provisioning issues addressed.                        |
| 16 | Primary Outcome                    | Confirm that Terraform successfully deployed the expected AWS infrastructure resources.                                | Infrastructure provisioning verified before further troubleshooting. |

## 2. Check Instance State

Verify EC2 Instance Availability, Health, Networking, and Security Configuration

| #  | Troubleshooting Activity        | Engineering Implementation / Verification                                                                   | Expected Outcome                                       |
| -- | ------------------------------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 1  | Confirm EC2 Instance State      | Verify Ubuntu and RHEL EC2 instances are in the expected running state.                                     | Required Linux instances running.                      |
| 2  | Verify Instance Health          | Review EC2 instance and system status checks.                                                               | Instance health and operational status confirmed.      |
| 3  | Review Security Groups          | Inspect inbound and outbound rules, particularly approved SSH TCP port 22 access.                           | Required network access rules verified.                |
| 4  | Confirm Subnet Routing          | Verify subnet route tables and required network paths.                                                      | Expected routing configuration confirmed.              |
| 5  | EC2 Instance Identification     | Confirm instance identifiers, names, operating systems, and associated AWS resources.                       | Correct target instances identified.                   |
| 6  | Ubuntu Instance Verification    | Confirm the Ubuntu instance was provisioned with the intended image and configuration.                      | Ubuntu deployment status verified.                     |
| 7  | RHEL Instance Verification      | Confirm the Red Hat Enterprise Linux instance was provisioned with the intended image and configuration.    | RHEL deployment status verified.                       |
| 8  | Public IP Address Verification  | Retrieve the public IPv4 addresses assigned to the managed instances.                                       | Correct management connection targets identified.      |
| 9  | VPC Network Verification        | Inspect the VPC associated with each instance.                                                              | Expected network placement confirmed.                  |
| 10 | Subnet Placement Verification   | Confirm the instances are deployed into their intended public subnets.                                      | Correct subnet placement verified.                     |
| 11 | Network Interface Inspection    | Review instance network interfaces and associated private/public addressing.                                | Instance networking information confirmed.             |
| 12 | Internet Gateway Verification   | Verify required internet gateway attachment and public subnet connectivity configuration.                   | External connectivity prerequisites identified.        |
| 13 | Network Access Control Lists    | Inspect subnet network ACLs when connectivity restrictions may affect traffic.                              | Subnet-level traffic controls verified.                |
| 14 | SSH Access Rules                | Confirm SSH is permitted only from approved administrative source addresses.                                | Controlled remote management access.                   |
| 15 | Instance Status Troubleshooting | Investigate failed EC2 health checks, incorrect network placement, or unexpected instance states.           | Probable instance-level failures isolated.             |
| 16 | Cloud Resource Cost Review      | Identify unnecessary active instances or other AWS resources requiring cleanup.                             | Improved cloud resource awareness.                     |
| 17 | Primary Outcome                 | Ensure EC2 instances are running, healthy, correctly configured, and connected to the intended AWS network. | Instance availability and network readiness confirmed. |

## 3. Test Connectivity

Verify Network Reachability, SSH Access, Authentication, and Firewall Configuration

| #  | Troubleshooting Activity           | Engineering Implementation / Verification                                                                | Expected Outcome                                                               |
| -- | ---------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 1  | Test Instance Reachability         | Perform ICMP testing where permitted by instance firewall rules, Security Groups, and network policies.  | Network reachability information collected.                                    |
| 2  | Verify SSH TCP Port 22             | Test TCP connectivity to port 22 on the Ubuntu and RHEL instances.                                       | SSH network-level accessibility confirmed.                                     |
| 3  | Confirm Public IP Addresses        | Compare connection targets with current EC2 public IP addresses.                                         | Correct destination addresses verified.                                        |
| 4  | Validate SSH Keys                  | Confirm the correct SSH private key is used and has appropriate file permissions.                        | SSH key configuration verified.                                                |
| 5  | Verify SSH Usernames               | Confirm the correct operating-system-specific administrative username is used for each instance.         | SSH connection parameters verified.                                            |
| 6  | Inspect Security Group Rules       | Verify approved inbound SSH access and required outbound connectivity.                                   | SSH traffic permitted according to security requirements.                      |
| 7  | Network Route Verification         | Inspect VPC routing and public subnet connectivity.                                                      | Required network paths verified.                                               |
| 8  | Internet Gateway Verification      | Confirm external connectivity is supported by the configured internet gateway and routing.               | Public connectivity prerequisites verified.                                    |
| 9  | Network ACL Verification           | Inspect subnet network ACL rules for restrictions affecting management traffic.                          | Subnet traffic filtering verified.                                             |
| 10 | Instance Firewall Verification     | Inspect Linux host firewall settings where relevant.                                                     | Host-level traffic restrictions identified.                                    |
| 11 | SSH Service Verification           | Confirm the SSH service is installed, running, and listening on the expected interface and port.         | SSH service availability verified.                                             |
| 12 | SSH Authentication Testing         | Attempt authorized SSH authentication using approved credentials and connection parameters.              | Successful or unsuccessful authentication distinguished from TCP reachability. |
| 13 | Ansible SSH Connectivity           | Verify that Ansible can connect to managed Linux instances using the configured inventory.               | Configuration management connectivity confirmed.                               |
| 14 | SSH Timeout Troubleshooting        | Investigate unreachable instances, incorrect IP addresses, blocked ports, and routing problems.          | Network connectivity failures isolated.                                        |
| 15 | SSH Authentication Troubleshooting | Investigate invalid usernames, incorrect keys, restrictive key permissions, and authentication failures. | Administrative authentication issues identified.                               |
| 16 | Python Connectivity Testing        | Execute Python TCP port 22 reachability checks against managed instances.                                | Automated connectivity evidence collected.                                     |
| 17 | Connectivity Evidence              | Preserve SSH diagnostic output, connection results, and Python validation records.                       | Reusable troubleshooting documentation.                                        |
| 18 | Primary Outcome                    | Confirm network connectivity and authorized SSH access to Ubuntu and RHEL EC2 instances.                 | Secure management connectivity verified.                                       |

## 4. Check Configuration

| #  | Troubleshooting Activity            | Engineering Implementation / Verification                                                            | Expected Outcome                                                         |

| 3  | Verify Permissions and Services     | Inspect relevant Linux permissions, account settings, and configured services.                       | Intended operating system configuration verified.                        |
| 4  | Investigate Failed Tasks            | Review failed or unreachable Ansible tasks and associated error messages.                            | Configuration management problems identified.                            |

| 7  | Ansible Playbook Structure          | Review task definitions, modules, variables, privilege escalation, and execution order.              | Playbook configuration consistency confirmed.                            |
| 8  | Ubuntu Configuration Verification   | Confirm required configuration tasks completed on the Ubuntu instance.                               | Ubuntu system administration validated.                                  |
| 9  | RHEL Configuration Verification     | Confirm required configuration tasks completed on the RHEL instance.                                 | RHEL system administration validated.                                    |
| 10 | Administrative User Verification    | Confirm the expected `test_user1` account exists on both target instances.                           | User provisioning verified.                                              |
| 11 | Privilege Configuration             | Verify approved administrative permissions and privilege escalation settings.                        | Controlled Linux administration confirmed.                               |
| 12 | SSH Connection Variables            | Inspect Ansible SSH configuration, user settings, and key references.                                | Appropriate authentication parameters confirmed.                         |
| 13 | Ansible Module Compatibility        | Verify playbook modules are appropriate for the target Linux distributions and administrative tasks. | Supported configuration operations identified.                           |
| 14 | Configuration Drift Investigation   | Compare expected configuration settings with observed Linux system state.                            | Unexpected configuration differences identified.                         |
| 15 | Ansible Error Handling              | Investigate permission errors, missing dependencies, failed modules, and unreachable hosts.          | Configuration failures isolated.                                         |
| 16 | Controlled Configuration Correction | Correct approved playbook, inventory, or Linux configuration issues.                                 | Intended administrative configuration restored.                          |
| 17 | Playbook Re-Execution               | Rerun validated Ansible playbooks and inspect execution results.                                     | Corrective configuration actions verified.                               |
| 18 | Configuration Documentation         | Record relevant Ansible output, user verification, configuration findings, and corrective actions.   | Reusable Linux configuration evidence.                                   |
| 19 | Primary Outcome                     | Ensure Ubuntu and RHEL instances are correctly configured and ready for their intended functions.    | Standardized Linux administration and configuration management verified. |
