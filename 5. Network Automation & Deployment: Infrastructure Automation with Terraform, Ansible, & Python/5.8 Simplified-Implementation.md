# Project 5 – Network Automation & Deployment: Infrastructure Automation with Terraform, Ansible, & Python

## 5.8 Simplified Implementation

Project 5 follows a structured six-phase implementation lifecycle to define cloud infrastructure requirements, provision AWS resources with Terraform, configure Linux servers using Ansible, validate SSH connectivity through Python, generate CSV reports, and document the deployment process.

![Project 5 — Simplified Implementation](infographics/5.8%20Simplified-Implementation.png)

Implementation Workflow: Plan → Provision → Configure → Validate → Document → Succeed.

## 1. Write Terraform Code

Provision AWS Cloud Infrastructure Using Infrastructure as Code

| #  | Implementation Activity            | Engineering Implementation                                                                                       | Expected Result                                                |
| -- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 1  | Infrastructure Requirements        | Define AWS resources, Linux instance specifications, networking, security requirements, and validation criteria. | Documented infrastructure implementation plan.                 |
| 2  | Automation Environment             | Prepare the development workstation with Terraform, AWS CLI, and required credentials.                           | Functional infrastructure provisioning environment.            |
| 3  | Terraform Configuration            | Create reusable Terraform configuration files defining AWS networking, compute resources, and security controls. | Infrastructure definitions ready for execution.                |
| 4  | VPC Provisioning                   | Define the AWS Virtual Private Cloud and its address space.                                                      | Logically isolated cloud network.                              |
| 5  | Subnet Configuration               | Define public subnets for Ubuntu and RHEL instance placement.                                                    | Organized cloud network segmentation.                          |
| 6  | Network Routing                    | Configure the required route tables, internet gateway connectivity, and network paths.                           | Intended cloud connectivity established.                       |
| 7  | Security Groups                    | Define approved inbound and outbound traffic rules, including restricted SSH access.                             | Controlled instance-level network access.                      |
| 8  | Ubuntu EC2 Deployment              | Define and provision an Ubuntu Linux EC2 instance.                                                               | Ubuntu cloud server created.                                   |
| 9  | RHEL EC2 Deployment                | Define and provision a Red Hat Enterprise Linux EC2 instance.                                                    | RHEL cloud server created.                                     |
| 10 | Terraform Initialization           | Execute `terraform init` to initialize the working directory and required providers.                             | Terraform dependencies initialized.                            |
| 11 | Terraform Configuration Validation | Execute `terraform validate` to verify configuration syntax and structural validity.                             | Terraform configuration validated.                             |
| 12 | Terraform Planning                 | Execute `terraform plan` and review proposed resource changes.                                                   | Infrastructure deployment plan reviewed.                       |
| 13 | Terraform Deployment               | Execute `terraform apply` after reviewing the proposed changes.                                                  | AWS infrastructure provisioned.                                |
| 14 | AWS Resource Verification          | Confirm that the expected VPC, subnets, Security Groups, and EC2 instances were created.                         | Infrastructure deployment verified.                            |
| 15 | Public IP Collection               | Record the public IP addresses assigned to the Ubuntu and RHEL instances.                                        | Connection targets available for configuration and validation. |
| 16 | Infrastructure Troubleshooting     | Review Terraform execution output and investigate failed resource creation or configuration errors.              | Provisioning issues identified and corrected.                  |
| 17 | Primary Deliverable                | Terraform configurations and deployed AWS networking, security, and Linux compute resources.                     | AWS infrastructure deployed and ready for configuration.       |

## 3. Validate with Python

Verify Infrastructure Connectivity and Generate Structured Deployment Reports

| #  | Implementation Activity        | Engineering Implementation                                                                                         | Expected Result                                  |
| -- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| 1  | Python Validation Environment  | Prepare Python and the required libraries for infrastructure connectivity testing.                                 | Functional validation environment.               |
| 2  | Python Script Development      | Develop a reusable script for testing connectivity to deployed EC2 instances.                                      | Automated infrastructure validation script.      |
| 3  | Instance Inventory             | Define the Ubuntu and RHEL hostnames, operating systems, and public IP addresses used for validation.              | Accurate validation targets.                     |
| 4  | TCP Port 22 Testing            | Test TCP connectivity to SSH port 22 on each EC2 instance.                                                         | SSH network-level accessibility verified.        |
| 5  | Ubuntu Connectivity Validation | Execute the connectivity test against the Ubuntu instance.                                                         | Ubuntu SSH port reachability result recorded.    |
| 6  | RHEL Connectivity Validation   | Execute the connectivity test against the RHEL instance.                                                           | RHEL SSH port reachability result recorded.      |
| 7  | Connection Status Collection   | Record successful or unsuccessful TCP connection results.                                                          | Structured connectivity status information.      |
| 8  | Hostname Collection            | Record the server hostname or inventory identifier.                                                                | Identifiable infrastructure validation records.  |
| 9  | Operating System Collection    | Record the operating system associated with each managed instance.                                                 | Clear Ubuntu and RHEL identification.            |
| 10 | Public IP Collection           | Record the public IP address used for each connectivity test.                                                      | Traceable validation connection targets.         |
| 11 | Validation Timestamp           | Record the date and time of each validation run.                                                                   | Time-referenced connectivity evidence.           |
| 12 | CSV Report Generation          | Generate a CSV report containing instance details and connectivity results.                                        | Structured deployment validation report.         |
| 13 | Error Handling                 | Handle unreachable hosts, connection timeouts, invalid targets, and script execution failures.                     | Reliable validation execution.                   |
| 14 | Report Verification            | Inspect CSV output for expected fields, valid formatting, and accurate connection results.                         | Validated reporting evidence.                    |
| 15 | Troubleshooting                | Investigate failed connectivity tests using AWS network settings, Security Groups, routing, and SSH configuration. | Connectivity problems identified.                |
| 16 | Repeat Validation              | Rerun the script after approved corrective actions.                                                                | Updated connectivity results recorded.           |
| 17 | Validation Evidence            | Preserve Python execution output and CSV reports for engineering documentation.                                    | Reusable infrastructure verification evidence.   |
| 18 | Primary Deliverable            | Python connectivity validation script and structured CSV status report.                                            | Connectivity validated and CSV report generated. |

TCP port 22 reachability confirms network-level accessibility to the SSH port. Successful SSH authentication, Linux configuration, and application functionality require separate verification.

## 6. Detailed Implementation Methodology

| 3     | Configure | Create Ansible inventories and playbooks, establish SSH authentication, configure Linux instances, and create approved administrative accounts.             | Configured Ubuntu and RHEL instances.                                     |

| 6     | Document  | Capture deployment procedures, configuration records, logs, screenshots, validation reports, and GitLab history.                                            | Final engineering documentation and version-controlled project artifacts. |
